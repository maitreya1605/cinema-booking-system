## 3. Analysis of Critical Test Steps

### Step 9 & 10: Atomic Reservation & Finalization
- **Action:** Customer requests reservation for seats `["A1", "A2"]`.
- **Database Query:** Executes `findOneAndUpdate({ _id: showId, bookedSeats: { $nin: ["A1", "A2"] } }, { $addToSet: { bookedSeats: { $each: ["A1", "A2"] } } })`.
- **Assertion:** Returns `201 Created` with a new `Booking` document in `Reserved` status.
- **Confirmation:** Payment confirmation flips `bookingStatus` to `Confirmed` and `paymentStatus` to `Completed`.

### Step 14 & 15: Single-Entry Ticket Gate Validation & Duplicate Rejection
- **First Scan (Step 14):**
  - **Request:** `POST /api/admin/validate-ticket` with booking ID.
  - **State Check:** `booking.isCheckedIn === false`.
  - **Result:** Returns `200 OK` ("Ticket verified successfully! Customer admitted.").
  - **State Transition:** Atomically marks `isCheckedIn = true` and `checkedInAt = new Date()`.
- **Second Scan (Step 15 - Negative Test):**
  - **Request:** Immediate re-scan of the same booking ID.
  - **State Check:** `booking.isCheckedIn === true`.
  - **Assertion:** Rejects with **`HTTP 409 Conflict`**:
    ```json
    {
      "valid": false,
      "error": "DUPLICATE ENTRY DETECTED",
      "message": "Ticket was ALREADY ADMITTED at 11:50:46 AM. Single-entry pass cannot be reused."
    }
    ```
  - **Security Outcome:** Prevents ticket forwarding, screenshot sharing, and unauthorized double-admissions.

### Step 16: Audit Trail Verification
- **Action:** `GET /api/admin/audit-logs` retrieves the immutable activity log.
- **Assertion:** Confirms that `TICKET_VALIDATED`, `BOOKING_CONFIRMED`, and `SHOW_CREATED` actions were recorded with exact user timestamps.
